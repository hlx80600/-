## A. 新机 / 换型 — 总顺序（必须按序）

```text
① 本机设备（对照 USB / 网卡 IP）→ 设置 → 通信与设备（IP/CAN/Mock）→ 保存 → 重启程序
② 负载工具（手爪 TCP / 抓鞋负载）→ 保存并下发
③ 示教点位（进入点、槽点、偏移）→ 保存
④ 运动参数（各步速度/是否平滑）→ 保存
⑤ 压机信号（槽号顺序、地址）→ 保存
⑥ 视觉（总页子页签：ROI→内参→手眼→检测测试；采图训练五步台；视觉方案流程图）
   拍过图后到「报警记录 → 运行快照」核对原图/叠图（文件名含相机与时间）
⑦ 屏蔽取料（仅 cam1 模拟时）
⑧ 夹爪调试（单机开合确认）
⑨ 空跑联调 / 工位调试单步
⑩ 总览：自动 → 初始化 → 启动
```

**原则：** 先通设备与示教，再做视觉标定；视觉未好之前用 Mock + 屏蔽取料空跑。

## B. 各界面怎么做（按导航顺序）

### 1. 总览（运行监控）

左侧名称是 **总览**。页内五个子页签：

| 子页签 | 里面有什么 |
|--------|------------|
| 总览 | 初始化/启动/暂停/停止/急停、模式、当前槽号**显示**、Mem1～10 |
| 连接工位 | 本机设备是否已连、Station1～6 忙闲与当前步 |
| 速度平滑 | **运行速度**、**初始化速度**（两套分开）、路径平滑总开关 |
| 手动 IO | 夹爪开合、压机旋转/压合线圈、皮带光电/急停 Mock |
| 空跑快控 | 一键空跑、光电与槽位 Mock 勾选 |

总览页**没有**一条全局速度条。臂速 =「速度平滑」运行速度% ×「运动参数」该步 vel%。

| 做什么 | 怎么做 |
|--------|--------|
| 每日生产 | 模式「自动」→ **初始化**（灯黄闪）→ 黄+绿（READY）→ **启动**。真机两臂须在 home 附近（允许 mm/° 在总览或 **设置 → 运动融合**） |
| 暂停 | 可改记忆，再点启动继续，**不必再初始化** |
| 停止 | 立刻停双臂；压机「放鞋完成」「启动」各清 **一次**（之后点表可手改）。**必须再初始化**才能启动 |
| 急停 | 工控机急停同时发给压机（点表 host_estop）。急停复位 → 报警复位 → 再初始化 |
| 当前槽号 | 只显示。改顺序、Mock 改取放槽号到 **压机信号** |
| 打开相机 / 示教器 | 顶栏按钮，独立窗口 |

**不要：** 自动运行中改记忆。停止后直接点启动（会被拒绝）。空跑**不会**自动把压机改成 Mock。

「模拟记一件」只测看板，不驱动机械。下料放到皮带（Station5）才记真件数。

### 3. 工位调试

| 步骤 | 操作 |
|------|------|
| 1 | 总览：模式 **单步** → 初始化 → 启动 |
| 2 | 本页选 Station（1～6）与 Auto |
| 3 | **武装所选 Auto**（互锁不够可勾「调试旁路」，需 yaml 允许） |
| 4 | **执行当前步** / **下一步** |
| 5 | **中止本 Auto** 清步号；记忆仍在总览改 |

用于：单独验证取料、放料、压合等，不必整线自动。

### 4. 运动参数

按程序步改 `vel` / `acc` / `blend`（如 `s2a10_90`）。  
**退回进入点、下压取料点等关键步建议 blend=关（到位）**，否则会未到点就写记忆。保存写回 yaml。

### 5. 视觉（总页）

左侧导航仅 **「视觉」** 一项。上方常驻相机预览；下方子页签：

| 子页签 | 内容 |
|--------|------|
| 相机与ROI | Mock、serial 绑定、ROI 绿框 |
| 棋盘格内参 | 检测/采集/计算内参 |
| 手眼标定 | 点像素采样、求解、写入 json |
| 视觉参数 | 按当前相机改置信度、鞋头前推、压杆检测区等，一点保存 |
| 检测测试 | YOLO 各路测试、PickPose / MoveL |
| 采图训练 | 深度学习五步台：采集→标注→训练→验证→模型（Ultralytics），首次点开再加载 |
| 视觉方案 | 精简流程图（图像源/ROI/深度学习/手眼/输出），只预览不改 GVL |

**运行快照**不在本总页：左侧 **报警记录** → 第四个页签 **运行快照**（完整说明见 **§14.4**）。

#### 5.1 采图训练（深度学习五步）

页内顶部选工程槽位（6 个产线槽或自定义工程），再按步骤条：

| 步骤 | 内容 | 操作要点 |
|------|------|----------|
| 采集 | 拍图 | 拍 1 / 连拍 / 文件夹导入 / 从 `logs/vision_snaps` 失败图导入；分类先选类（快捷键 1/2） |
| 标注 | 圈目标 | 分类整图；检测拖矩形；OBB 滚轮旋转；分割多边形。多类、上一张/下一张、撤销 |
| 训练 | Ultralytics | 基本：规格 n/s/m、epochs、imgsz、batch、CPU/GPU、早停、从 last.pt 继续或生产权重微调。高级可展开学习率/增强。曲线读 `results.csv`，可终止 |
| 验证 | 测模型 | 当前预览叠图、val 指标、混淆矩阵、文件夹批量。皮带 OBB 必须用 cam1 实图确认（产线可能仍走 ultralytics_obb360） |
| 模型 | 启用/导出 | 挂接旧模型（可选手选目录，只补缺失软链）、一键从旧工程（可选拷 datasets/runs）、选 .pt、导入权重/数据集/runs、启用到产线、导出 ONNX。导入不改产线，验证后再启用。自定义工程必须映射到 6 槽之一。不覆盖 `custom_*.pt`。 |

手眼 / 内参 / 皮带试走仍在「棋盘格 / 手眼 / 检测测试」。左右脚可在本页重训。点像素在上方预览区点。

「检测测试」测皮带 / 放料槽 / 取料槽会写入运行快照，查图到 **§14.4**。视觉页「截图保存」是标定图（`config/vision_snaps/`），不是运行快照。

### 6. 视觉标定顺序（ROI / 内参 / 手眼）— ★ 详细

对 **每一路需要真机视觉的相机**（通常至少 cam1）按下面做。

#### 6.1 准备工作

1. 「设置 → 通信与设备」里该相机 Mock 关掉，填好 **serial**，保存并重启。  
2. 打开「视觉」，下拉选中相机（cam1～cam4）。  
3. 「相机与ROI」→「枚举设备」→ 核对列表 → 「绑定 serial 并重开」。  
4. 预览有图；可开「相机监控窗口」对照。

#### 6.2 ROI 绿框（先做）

1. 拖绿框或「中间半张图」/「铺满整张图」。  
2. **写入配置（保存 ROI）** → 文件 `config/roi/<相机>.json`。  
3. cam1 投产时再点「ROI 写入皮带 json」（手眼页签，进 shoe_vision_config）。

#### 6.3 棋盘格内参

默认内角点 **11×8**、格边 **15mm**（可在 yaml `vision.chessboard` 改，须与实物一致）。

1. 棋盘格放在该相机视野内、铺满尽量多角度。  
2. 点 **检测棋盘格** → 画面有角点才算有效。  
3. 点 **采集有效帧**（多采 10～20 帧，变换角度/距离）。  
4. **计算并保存内参** → `config/calib/<相机>_intrinsics.json`。  
5. cam1：再点 **内参写入皮带 json**。

#### 6.4 手眼标定（cam1 皮带必做；其它相机按需）

目标：像素点 ↔ 上料臂基座/TCP，使「测试皮带拍照」出的 XY 能用于取料。

**推荐采点方式（eye-to-hand 常见做法）：**

1. 上料臂装好标定针/尖点（或夹爪尖），示教器手动。  
2. 在预览画面 **点击** 针尖对应像素（出现待写入像素）。  
3. 针尖停稳后，点 **记录手眼采样点**（自动读当前 TCP）。  
4. **换位置** 重复：建议 **≥ 8～12 点**，铺满皮带工作区，高低略变。  
5. **保存手眼采样**（可随时存盘）。  
6. **计算手眼 4×4 写入 json** → `config/calib/<相机>_handeye.json`；cam1 同时写入 `shoe_vision_config.json`。  
7. 用 **测试皮带拍照** 看 X/Y/鞋长/鞋头偏移是否合理 → **视觉结果写入 PickPose** → **MoveL 到取料上方** 目视是否对准。

**注意：**

- 必须先有内参，再求解手眼。  
- 采样时 TCP 与像素必须是同一时刻姿态。  
- 算错可「清除手眼采样 / 清除手眼矩阵」后重采。  
- 手眼改完一般 **重启程序** 再跑自动最稳。

#### 6.5 各路「测试」按钮对照

| 按钮 | 相机 | 说明 |
|------|------|------|
| 测试皮带拍照 | cam1 | Station1 同源；看楦心、鞋长、鞋头偏移 |
| 测试鞋头对位 | cam2 | 到位 / 需向前 |
| 测试放料槽 / 槽有无鞋 | cam3 | 空/有料 |
| 测试取料槽 / 压杆偏移 | cam4 | 有料 + 压杆 XY |
| 测试贴边引导 | cam2 相关 | 引导偏移 |

某路缺模型或 Mock=开 → 走模拟结果；皮带 Mock 用「屏蔽取料」示教点。

### 7. 示教点位

| 臂 | 必教点 |
|----|--------|
| 上料 R1 | `home`，`pick_entry`，`pick_above_offset`，`place_entry`，`place_slot`，`place_above_offset` |
| 下料 R2 | `home`，`slot_pick_entry`，`slot_pick`，`slot_pick_above_offset`，`belt_place_entry`，`belt_place`，`belt_place_above_offset` |

操作：选点 → 点 **打开示教器**（或顶栏「示教器」）挪到位 → **读入当前 TCP+关节** → **保存当前点**。  
**按住 MoveJ/MoveL 到此点** 才运动，松开立刻停；到位会弹窗。点按不会动。  
试跑速度用本页 **速度条**（默认 8%，上限 25%），不改总览「速度平滑」、也不影响自动。  
取料 XY 常由视觉写入；`*_above_offset` 为相对偏移。改完可路径试跑。

#### 7.1 示教器（独立窗口）

主界面右上 **示教器**，或本页 **打开示教器**：弹出独立窗口，不必离开当前页、也不必切法奥示教器。  
选上料/下料臂，坐标系选基座 XYZ / 工具 XYZ / 关节。默认 **按住连续**（按住才动，松开立刻停）；**点按一步** 按设定 mm/° 走一次。  
默认窗口置顶，可一边看点位一边点动。速度上限 25%，建议先 **8%～15%**。  
自动连续运行、急停、报警时锁定。关示教器窗口即停点动。夹爪开合仍用「夹爪调试」。

**仅当 cam1 为 Mock**（无相机/未标定时）必做：录入左右鞋示教 XY/角度/鞋头偏移，保存。  
真机 YOLO+手眼成功后可不用本页。

### 9. 空跑联调

无真皮带时：点 **一键启用空跑**（总览「空跑快控」同样有入口）。  
空跑会维持光电/槽位时序，**不改设置里各设备的 Mock 勾选**。

| 选项 | 作用 |
|------|------|
| 保持皮带光电=有料 | Station1 能进 |
| 放料槽自动跟手 | 空槽 + 左右跟手中鞋，避免 Mem10 卡死 |
| 取料槽自动有料时序 | 未拍时有料供 S4/S5；取完后无料，不提前清 Mem6 |
| Mock 压鞋/旋转延时 | 仅当 **压机本身是 Mock** 时，空闲会先忙再恢复 |

要手改取放槽号、在点表里模拟转盘：到 **设置 → 通信与设备** 勾「压鞋机 模拟」。  
配合「屏蔽取料」+ 相机 Mock，可在总览走通 Station1～6。点 **保存空跑选项到 yaml** 下次还在。

### 10. 负载工具

分别设 **未抓鞋（负载1 + 工具TCP1）** / **抓鞋（负载2 + 工具TCP2）** 的质量、质心、TCP。  
绿色框和「● 当前使用」表示本臂**正在用哪一套**；上方状态栏同时写清当前负载编号和运动工具/TCP。  
「切到 1 / 切到 2」会**同时**切换负载和工具 TCP。自动取料夹紧后可能出现负载2、仍用工具1，状态栏会黄底提示。  
保存并可勾选下发到控制器。抓取后鞋头 TCP 由流程按视觉偏移改写工具2列表。

### 11. 压机信号

页内分页：**中科院点表** / **实时信号** / **地址**。

中科院点表内部再分：**联机/公共**、**压机手动**、**压杆**、**压着时间**。页顶是槽号顺序与取放槽号。

| 做什么 | 怎么做 |
|--------|--------|
| 槽号顺序 | 页顶选 12341 正序或 43214 反序，立刻写入 yaml |
| 改取放槽号 | **仅压机 Mock** 时可改并点「应用槽号」。真机跟 PLC「当前工位显示」，控件是灰的 |
| 联机点表 | 空闲、放鞋完成、启动、当前工位、取料槽工作完成。联机模式要开。启动=1 空转、=2 启动 |
| 取料槽工作完成 | **只读**，压机 PLC 给出；卡片写「当前工位 #N → 取料槽 #M」 |
| 点进 / 点退 | **压杆**分页，两个**保持型**按钮（按住才输出，松开关） |
| 放鞋完成置 1/0 | 联机卡片可写；启动必须在放鞋完成=1 且满保持时间之后 |
| 地址 | 「地址」页签改开口约定、自算槽号、各槽 Modbus Dec，点保存 |

报警会写明是哪台设备（压鞋机 / 上料臂 / 下料臂等）。联机握手见 **§E**。

### 12. 夹爪调试

掉线或 GRIP_* 报警：先确认 CAN 已 `ip link` 拉起、48V 已上电，再点 **报警复位**。详见 [夹爪使用说明.md](夹爪使用说明.md)。

### 13. 设置

左侧 **设置**，五个子页签：

| 页签 | 做什么 |
|------|--------|
| 语言 | 界面语言，立即更新导航/总览/使用说明 |
| 界面与刷新 | 前台快刷/慢刷、失焦刷新、相机预览 fps；**开机登录后自动启动本程序**（工控机须同时开系统自动登录） |
| 运动融合 | 路径平滑总开关与 T/R/延时；初始化允许偏离 home 的 mm/° |
| 通信与设备 | 机器人 IP、压机、夹爪 CAN、相机 serial、**各设备 Mock**；压机「等空闲变0超时」「放鞋完成后等启动/空转」（毫秒） |
| 手机监控 | 本机开网页遥控的端口与口令；总览会显示访问地址 |

**通信与设备** 保存后：IP / serial / Mock 建议 **重启 `python3 main.py`**。超时与保持时间写入后立刻生效，一般不用重启。  
填 IP / serial 前先打开 **本机设备** 对照网卡和 USB 序列号。

### 13.5 本机设备（USB / IP）

左侧导航 **本机设备**（在「设置」和「报警记录」之间）。只读列出：

| 表 | 看什么 | 填到哪里 |
|----|--------|----------|
| 网络与 IP | 网卡名、以太网/CAN/无线、状态、IPv4/IPv6、MAC；抬头有主机名和默认网关 | **设置 → 通信与设备** 里机器人 / 压机 IP（须与工控机同一网段） |
| USB 设备 | 总线号、VID:PID、名称、序列号、tty/video/网卡子节点 | **设置 → 通信与设备** 相机 serial |
| 串口 / 相机节点 | `/dev/serial/by-id`、`/dev/v4l/by-id` 及实际设备 | 串口调试、V4L 相机路径 |

点 **刷新** 重新扫描；双击单元格复制该项；**复制全部** 得到可贴到聊天/工单的纯文本。  
不调用奥比相机 SDK（避免卡住）；深度相机仍会出现在 USB / V4L 表。Linux 工控机有效；容器或无 `/sys/bus/usb` 时表可能为空。

### 14. 报警记录

左侧导航 **报警记录**。四个页签：**本次运行** / **落盘错误** / **黑匣子** / **运行快照**。  
文件都在项目 `logs/`（不进 git）。「打开日志目录」打开整个 `logs/`；运行快照页另有「打开视觉log文件夹」，只打开 `logs/vision_snaps/`。

| 页签 | 看什么 | 退出程序后再开 |
|------|--------|----------------|
| 本次运行 | 当前这次启动后的报警 | 否（请看落盘错误 / 黑匣子） |
| 落盘错误 | WARNING / ERROR / 报警写入磁盘 | 是 |
| 黑匣子 | 故障前后运行轨迹；崩溃另有 `logs/dumps/` | 是 |
| 运行快照 | 生产拍照原图/叠图 + 运送回写 | 是 |

#### 14.1 本次运行

当前启动后的报警，**分页**（每页 20 条，新的在前）。可选中后复制、报警复位、打开可复制窗口。  
刷新时若正在选中某条，不会清掉选区。退出程序后本页清空，历史请切「落盘错误」或「黑匣子」。

弹窗和列表都会写清 **设备**、**故障类型**、**代码**、**详情**、**处理**。运动失败会报到上料/下料臂，不再笼统写成「本机程序」。

| 代码 | 故障 | 常见处理 |
|------|------|----------|
| LINK | 真机通讯断开 | 查该设备网线/CAN/IP；连上后报警复位；运行中掉线要再初始化 |
| ROBOT1 / ROBOT2 | 上料/下料臂本体或运动 | 示教器消红 → 报警复位；看详情里的路径起止点 |
| PRESS | 压鞋机 | 网线、联机模式、空闲 |
| GRIP_* | 夹爪 | CAN、48V；复位会重连 |
| INIT / INIT_HOME | 初始化 / 不在初始位 | 回 home 附近或放宽 mm/° |
| VISION1～4 | 对应相机拍照/对位 | serial、预览；Mock 可空跑 |
| PAYLOAD | 负载切换失败 | 该臂示教器 |
| OB1 | 本机未分类异常 | 复制全文给调试 |

#### 14.2 落盘错误

WARNING / ERROR / 报警写入 `logs/errors_YYYY-MM-DD.jsonl`（另有 `app_YYYY-MM-DD.log`、`error_YYYY-MM-DD.log`，文件名带当天日期）。  
同样分页；可刷新、复制本页。关机后再开程序仍能查。

#### 14.3 黑匣子

故障前后一段时间的运行轨迹（环形记录 `logs/blackbox_YYYY-MM-DD.jsonl`）。崩溃或严重错误时还会在 `logs/dumps/` 再打一份带时间戳的内存快照。  
这是**程序轨迹**，不是相机照片。相机照片在下一页签「运行快照」。

#### 14.4 运行快照（生产拍照 + 运送结果）

用来回答两件事：**当时相机看见什么**，以及 **后来运到哪里、运得对不对**。两者写在同一条记录上，可在触摸屏上翻，不必上工控机找文件夹。

##### 14.4.1 什么时候会存一张

| 时机 | 相机 | 说明 |
|------|------|------|
| Station1 皮带拍照 | cam1 | 自动每次拍照都存（成功/失败都存）。确认本拍取料位后，把编号挂到这只鞋上，后面运送结果写回这一条 |
| Station3 放料槽拍照 | cam3 | 空槽 / 有料、左右槽判定 |
| Station4 取料槽拍照 | cam4 | 有无料、压杆偏移 |
| 视觉「检测测试」手动测皮带 / 放料槽 / 取料槽 | 对应路 | 与生产同一套接口，方便对模型 |
| 「视觉结果写入 PickPose」 | cam1 | 也会带上本次编号；若接着跑自动放料，仍可回写运送结果 |

**不会存**（避免刷盘、也对不上「哪一只鞋」）：

- 顶部「相机监控」窗口的实时推演、监视定时刷新
- cam2 鞋头对位、贴边引导（运动中反复拍）
- 视觉页上方「截图保存」→ 标定截图，目录是 `config/vision_snaps/`，**不是**运行快照

##### 14.4.2 文件在哪、一张图怎么命名

根目录：`logs/vision_snaps/`。按日期：

```text
logs/vision_snaps/YYYY-MM-DD/<快照id>/
  cam1_20260828_140455_635_belt_pick_raw.jpg   原图
  cam1_20260828_140455_635_belt_pick_vis.jpg   叠了检测框/文字的图
  meta.json                                    检测结果 + transport（运送回写）
logs/vision_snaps/index_YYYY-MM-DD.jsonl   当日总索引
```

**JPEG 文件名** = `相机_日期_时刻毫秒_类型_raw.jpg` / `_vis.jpg`。拷文件时不必打开文件夹也能分辨是哪路相机、哪一刻。例如：

| 文件名片段 | 含义 |
|------------|------|
| `cam1` / `cam3` / `cam4` | 哪路相机拍的 |
| `20260828_140455_635` | 拍照时间（含毫秒） |
| `belt_pick` / `place_slot` / `pick_slot` | 类型（皮带取料 / 放料槽 / 取料槽） |
| `_raw` / `_vis` | 原图 / 叠图 |

快照文件夹 id 例：`20260828_111343_635_cam1_belt_pick`（时间 + 相机 + 类型）。  
旧记录若仍是 `raw.jpg` / `vis.jpg`，本页仍能打开。

##### 14.4.3 运送完成后再写回什么

写在该条 `meta.json` 的 `transport` 里。详情「运送结果」、列表右侧「已放槽#2 / 未运送 / 可放料 / 已下料」都读这里。

| 字段 | 何时写 | 写在哪条快照上 | 内容 |
|------|--------|----------------|------|
| `place` 放入鞋槽 | Station2 放料完成、回到 place_entry | cam1 皮带那一拍 | 成功与否、放料槽号、左右脚 |
| `slot_check` 槽判定 | Station3 判定结束 | cam3 本拍，并同步到正在运送的 cam1 那一拍 | 可放料 / 左右不配只转不压 / 槽内有料禁止放 |
| `unload` 下料到皮带 | Station5 放到皮带并记产量 | cam4 取料槽那一拍 | 成功与否、取料槽号 |

详情写「尚未回写」：还在途中，或只点了检测测试没跑自动。点 **刷新** 再看。

##### 14.4.4 在本页怎么查

1. 左侧导航 **报警记录** → 页签 **运行快照**（在「黑匣子」右边）。
2. **打开视觉log文件夹**：系统文件管理器打开 `logs/vision_snaps/`。
3. 左侧列表 **新的在前**；可按相机、类型筛选；每页 20 条。
4. 点一条：右侧 **原图、叠图**；下方检测数据（坐标、左右脚、鞋长、有无料等）和运送回写。
5. 刚放完料或刚下料：点 **刷新**，同一条上会出现「已放槽#n」或「已下料」。
6. **打开本条目录**：打开这一拍的文件夹，可拷带相机与时间的 jpg 和 `meta.json`。
7. **复制详情**：把当前说明拷到剪贴板。

不要和下面几个按钮搞混：

| 按钮 | 目录 | 用途 |
|------|------|------|
| 运行快照 → 打开视觉log文件夹 | `logs/vision_snaps/` | 生产运行记录，带运送结果 |
| 视觉页 → 截图目录 | `config/vision_snaps/` | 「截图保存」的标定图，无运送结果 |
| 视觉页 → 标定目录 / YOLO模型目录 | `config/calib/`、`models/` | 内参手眼、权重 |
| 报警记录 → 打开日志目录 | 整个 `logs/` | `app_日期.log`、黑匣子；视觉快照是其中的 `vision_snaps/` 子目录 |

##### 14.4.5 开关与保留

`config/default.yaml`：

- `vision.save_runtime_snaps`：默认 `true`；改 `false` 则完全不存
- `vision.snap_keep_days`：默认 `7`，过期日期目录会自动删

改完 **重启程序** 生效。

##### 14.4.6 排故怎么用

- 取偏、抓空：筛 cam1 / 皮带取料，对照叠图和 X/Y/Rz、左右脚、鞋长。
- 放错槽、只转不压：看 cam1 的 slot_check / place，以及 cam3 判定原文。
- 下料取空：筛 cam4，看有无料、压杆偏移，以及 unload 槽号。
- 列表仍「未运送」但流程已走完：先刷新；仍没有则看本页「本次运行 / 黑匣子」是否中途停过。
- 图显示「暂无」：JPEG 在后台写，等一两秒再刷新。

主界面顶部按钮打开。顶部页签 **原图 / 结果 / 深度** 整窗切换，四路 2×2，每格一张大图。勾「刷新原图」「实时推演」。

## E. 启停与压机联机（必读）

### E.1 初始化 / 暂停 / 停止

| 按钮 | 之后能否直接启动 | 压机联机字 |
|------|------------------|------------|
| 初始化 | 完成后（READY）可以 | **开始时清一次**「放鞋完成=0、启动=0」 |
| 暂停 | 可以，接着跑 | 不清这两个字 |
| 停止 | **不可以**，必须再初始化 | **清一次**放鞋完成、启动；之后不再周期写 0，点表可手改 |
| 急停 | 复位 + 报警复位后再初始化 | 急停按下时同样清一次 |

停止会清掉「初始化完成」标志。界面提示「已停止 — 请重新初始化」。

### E.2 放鞋完成 → 启动 / 空转

工控机发给压机 PLC：

1. 先写 **放鞋完成=1**（上料回进入点后、或禁放分支也置 1）。
2. **再等**「放鞋完成后等启动/空转」时间（默认 **500ms**，**设置 → 通信与设备** 里改）。这段只卡住写启动，**其它工位照常跑**。
3. 时间到且放鞋完成仍为 1：Mem10=1 则启动字=**1 空转**，否则 =**2 启动**。
4. 等空闲变 0（转盘开始忙）；超时见设置，0=一直等。
5. 再等空闲=1（转盘到位）→ 清启动、清放鞋完成，按顺序推进槽号。

点表上手动写启动/空转也要先有放鞋完成=1，并且满保持时间，否则会提示还差多少毫秒。

### E.3 取料槽工作完成

这是 **压机 PLC 给过来的**（只读），不是工控机写。跟 PLC「当前工位显示」推出取料槽后再读该槽线圈。Station4 拍照、Station5 取料都要等它 =1。Mock 时当前工位显示跟放料槽号走。

### E.4 空跑与压机 Mock

「启动空跑」**不会**强行把压机改成 Mock。要手改槽号、模拟转盘：在 **设置 → 通信与设备** 勾「压鞋机 模拟」。真机连着压机时取消勾选，点表应显示「压机已连接」而不是 Mock。

### E.5 各工位进入条件（自动运行、未暂停、本站不忙）

另需未急停、无报警。调试旁路可跳过部分互锁。

| 站 | 还要满足 |
|----|----------|
| S1 皮带拍照 | 皮带光电有料（空跑可维持） |
| S2 上料 | Mem1；取/放各 Auto 自己的记忆 |
| S3 放料槽拍照 | 空闲=1 等；禁放（左右不对或槽内有料）也会写放鞋完成=1 |
| S4 取料槽拍照 | 空闲=1，**取料槽工作完成=1**，Mem7=0 |
| S5 下料取料 | 空闲=1，**取料槽工作完成=1**，Mem6=1 |
| S6 压转 | Mem3=1，Mem7=1，Mem6=0，空闲=1 |

S2 回 `place_entry` 后写 Mem3=1 并放鞋完成=1；S6 再等保持时间后写启动。两臂并行：S5 不必等 S2 做完同一拍。

## F. 每日开工 / 收工

**开工**

1. 三色灯不是红闪；急停蘑菇头已复位。  
2. 总览「连接工位」：双臂、夹爪、压机、相机该连的都是已连接（不该连的才是 Mock）。  
3. 模式自动 → 初始化 → READY（黄+绿）→ 启动。  
4. 第一件看叠图：报警记录 → 运行快照。

**班中暂停**改 Mem 或清料：暂停 → 改完启动。不要用停止代替暂停。

**收工 / 换型停机**

1. 点 **停止**（不要只关窗口）。  
2. 确认点表放鞋完成、启动已是 0。  
3. 需要再开时：初始化 → 启动。

## G. 常见卡住

| 现象 | 先看 |
|------|------|
| 点启动没反应 | 是否刚点过停止？要先初始化。是否报警/急停/设备掉线 |
| 初始化立刻报警 | 两臂是否在 home 附近；设置 → 运动融合 里 mm/°；看报警里的设备名 |
| S4/S5 不进 | 空闲是否=1；取料槽工作完成是否=1（跟当前工位）；Mem6/Mem7 |
| S6 不写启动 | 放鞋完成是否已=1 且满保持时间；Mem3、Mem7、Mem6=0 |
| 点表启动写不进去 | 联机模式是否开；是否还没到保持时间；是否被停止清零后又周期手改（停止只清一次） |
| 设置里取消压机模拟，点表仍写 Mock | 看 **设置 → 通信与设备**「压鞋机 模拟」是否保存；空跑不会强行改这项 |
| 取放槽号改不了 | 真机不允许改；只有压机 Mock 时能改 |
| 报警只写「掉线」 | 现行报警会带设备名；到「连接工位」对一下 IP |
| 只转不压 | Mem10=1（左右不配）；看 cam3 判定与运行快照 slot_check |

写/清记忆的时机见 [程序总览.md](程序总览.md)。
