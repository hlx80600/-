# 四槽视觉 vs 双槽产线对账

对照仓库：双槽 `Casbot_Press_Shoes`（`shoe_vision_seg.py` 等）。  
本仓库：`Casbot_FourSlot_Press_Shoes`（工作区文件夹 `四槽压机`）。  
四槽只改视觉门面，**不改** `stations/` / `main.py` / `devices/` / `core/`。

控制 2026-09-20 更新后，Station1～6 视觉调用名与结果字段未变；视觉按新工位接口重接，不改工位步序。

现场相机 **4 路**（不是每槽一台顶视）：

| 相机 | 角色 | 装在哪 |
|------|------|--------|
| cam1 | 皮带上料 | 固定 |
| cam2 | 鞋头对位 | 上料臂眼在手上 |
| cam3 | 放料开口（上料槽） | 开口上方，槽转相机不转 |
| cam4 | 取料开口（下料槽） | 开口上方，槽转相机不转 |

PLC `place_slot` / `pick_slot`（1–4）表示**当前开口下是几号槽**。

## 接口差异

| 能力 | 双槽产线 | 四槽改前 | 四槽改后（视觉侧） |
|------|----------|----------|-------------------|
| 皮带抓取 | `ShoeVision`：鞋 OBB + 左右脚 + 楦 + 深度 + 手眼 | `detect_belt_legacy` 已接同一套 | 保持；字段仍是 `(x,y,z,yaw,is_left_shoe)`。同时两只时取**操作工视角左侧**（基座 X 最小），不是优先「左脚」类别 |
| 槽占用 | **检测** `slot_check_dect`（有框=有鞋）`7.13_dect_1.pt` | 部分路径曾走分类 | 默认走检测；分类仅作缺权重兜底 |
| 压杆/取鞋偏移 | `position.py`：鞋 X − 示教 preset X | `measure_rod_offset_mm` | 公式不变；按开口 cam4 + 可选 `slot_id` 取 preset |
| 鞋头对位 | ImgAct 双头 `0907best` + `_later`：X 停/前/后，Y 停/左/右 | YOLO 二分类 `0722best.pt` | 优先 ImgAct 推理；运动仍归 Station，本仓库不改 `toe_place_assist` |
| 槽语义 | 左/右两台槽相机 | 真机 cam3 曾写死 `is_left_slot=True` | 由当前 `place_slot` + `opening.left_slots`（默认 1/3 左、2/4 右）推导；工位不传槽号时视觉从 `ctx.press` 读取 |
| 手眼 | 单基座一张矩阵 | 配置里仍是皮带一份 | 装机后：cam1/cam2/cam3→robot1，cam4→robot2 |

## 控制同事继续用的接口（签名兼容）

Station 仍调用：

- `ctx.vision.photo_belt_pick(...)`
- `ctx.vision.photo_place_slot()` / `photo_pick_slot()`
- `algo.classify_toe_align(...)`（Station2 自己取图）
- `ctx.vision.last_pick_xy_offset_mm`

新增字段是附加的：`SlotPhotoResult.slot_id`、`ToeAlignResult.x_label` / `y_label`。旧字段含义不变。

`slot_id` 来源（不改 Station）：`photo_*(slot_id=)` → 调用栈里的 `ctx.press.place_slot/pick_slot` → `VisionService.set_opening_slots` → `vision.opening`。未设置时为 `0`。不要用 `press.mock_*_slot` yaml 初值冒充当前槽号。左右槽：`vision.opening.left_slots`（默认 `[1, 3]`）。

Mem（视觉不置 Mem3）：1 皮带拍完 · 2 上料爪有料 · 3 放料槽待压转 · 4 放料槽拍完 · 5 下料爪有料 · 6 取料槽有料 · 7 取料槽拍完 · 8 左鞋 · 9 右鞋 · 10 放料左右不匹配只转不压。

## 算法本体（必须在四槽仓库侧可用）

| 算法 | 双槽怎么来 | 四槽怎么来 |
|------|------------|------------|
| `casbot_yolo_obb360` | `init.sh` clone 进 `casbot_yolo_point4d/` | 同样：`bash init.sh` |
| `casbot_yolo_point4d` | `init.sh` clone 到仓库根 | 同样：`bash init.sh`（gitignore，不提交） |
| `DiscreteMultiActionHead` | 整棵 `shoe_align/ImgAct/` | 已从双槽拷入本仓库 `shoe_align/ImgAct/` |

体检：`python3 tools/check_vision_algo_deps.py`。路径由 `vision/algo_deps.py` 在 import 时挂上。`point4d`/`obb360` **不进 git**，和双槽一样用时 `bash init.sh`。

## 双槽实际用的不是「全是 obb360」

看双槽源码（不是口头）：

| 环节 | 双槽文件 | 实际加载 |
|------|----------|----------|
| 皮带鞋/楦 | `shoe_vision_seg.py` | `casbot_yolo_point4d` + `ultralytics_obb360` |
| 槽有无鞋 | `slot_check_dect.py` | `from ultralytics import YOLO` 跑 **detect** 权重 `7.13_dect_1.pt` |
| 压杆 | `position_obb.py` | **特意躲开** obb360 别名，用 pip 的 YOLO 加载普通 OBB |
| 鞋头 | `shoe_allign_controller_twice.py` | `ImgAct` / `DiscreteMultiActionHead`，不是 obb360 |

obb360 会把名字 `ultralytics` 劫持成自己。皮带先 import 之后，槽检测那句 `from ultralytics import YOLO` 在进程里可能已经是 obb360 的包装去跑 detect 权重——但权重仍是检测模型，不是 360° OBB 任务。压杆不能这么干，所以双槽单独写了隔离。四槽压杆沿用这段；槽检测与双槽相同用 `from ultralytics import YOLO`。

## 仍与双槽不同（硬件/胶水，算法栈按上表对齐）

| 点 | 双槽 | 四槽（不改 Station） |
|----|------|----------------------|
| 槽相机 | 左/右各一台顶视 | 放料口 cam3、取料口 cam4，槽转相机不转 |
| 结果槽号 | 左/右 | 附加 `slot_id`（1–4）；未设置时 `0` |
| `is_left_slot` | 按左/右相机 | 由当前放料槽号推导（默认 1/3 左、2/4 右）；Station3 仍读布尔，不改控制 |
| 鞋头运动 | `shoe_allign_*` 里边推边动 | 视觉只出类别；`toe_place_assist` 仍是控制同事的 |
| 皮带 json | 产线 `9.5` 左右脚/楦 | 本仓库 json 仍是 `7.23`/`7.24`/`custom_`，要换成产线权重 |
| 权重文件 | 工控机 `models/` | 本机多为断链，需另拷；**不要把大权重推进 git** |

## 安装与运行（视觉）

新机 / 新工控机在仓库根：

```bash
bash init.sh
python3 tools/check_vision_algo_deps.py
```

需要 GitHub SSH 和对 `RobotSkillsDevelopmentTeam` 的读权限。`CLONE_FULL=1 bash init.sh` 才拉完整历史。

然后按 [README.md](../README.md) 装 `requirements.txt`、`pyorbbecsdk`、`torch`/`ultralytics`。空跑可保持 `cameras.camN.use_mock: true`。

Gemini 336L：彩色和深度是两个口；彩色 Bayer 可能被 SDK 报成 `921600×1`，视觉按 `1280×720` 还原。`index4` 才是彩色，`index0` 深度，`index1/3/5` 是元数据（不要 `read`）。

## 现场还缺什么（不要用断链 `.pt`）

拷真实权重，视角变了再考虑重训。大文件不要进 git。

| 项 | 配置 / 路径 | 现场要做 |
|----|-------------|----------|
| 皮带鞋 OBB | `shoe_vision_config.json` → `shoe_model_path`（现 `7.23鞋obb.pt`） | 换成产线权重（双槽常用 `9.5` 或现场最新） |
| 左右脚分类 | 同上 `shoe_cls_model_path`（现 `custom_鞋头朝上左右脚分类.pt`） | 换成产线 `9.5鞋头朝上左右脚分类.pt` 一类 |
| 楦 OBB | 同上 `shoe_tree_model_path`（现 `7.24鞋楦obb.pt`） | 换成产线楦权重 |
| 槽检测 | `vision.slot_check.model_path` → `models/slot_check/7.13_dect_1.pt` | 拷检测权重；不要用分类 `.pt` 当主路径 |
| 鞋头 ImgAct | `vision.toe_align.model_path` + `later_model_path`（`0907best.pt` / `_later`） | 拷前进+侧向两份；缺则退 YOLO `0722best.pt` |
| 压杆 OBB | `vision.position.rod_model_path` → `models/position/rod/obb.pt` | 拷普通 OBB 权重 |
| cam1 手眼 + 内参 | `shoe_vision_config.json` 的 `handeye.mat` / `camera.fx…` | **本机重标**（四槽两基座，不能直接抄双槽单基座） |
| cam2 眼在手上 | `config/calib/cam2_*` | 装机后对 robot1 做手眼 |
| cam3 放料口 | 开口顶视 | 对 robot1；槽转相机不转，标定在开口下做 |
| cam4 取料口 | 开口顶视 | 对 **robot2**；压杆 preset 写进 `position_config.yaml` |
| 左右槽号 | `vision.opening.left_slots` 默认 `[1, 3]` | 装机若 1/3 不是左槽，只改 yaml |
| 相机 serial | `cameras.cam1～4.serial` | 填 336L 真机 serial，不要用错 index |

皮带 json 里的手眼矩阵是旧机台的，**四槽必须按基座重做**。
