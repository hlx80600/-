## 1. 程序是干什么的

工控机上的 Python 程序，控制：

- **上料臂 robot1**（法奥 FR5）：皮带取鞋 → 放进压鞋机槽  
- **下料臂 robot2**：从槽取鞋 → 放到下料皮带  
- **四路相机** + YOLO：找鞋、对位、槽有无鞋、压杆偏移  
- **压鞋机**：四槽压合与转台  
- **双夹爪**（CAN）  

默认 `config/default.yaml` 里设备多为 **Mock**：无真机也能开界面、看步号与记忆变化。

---

## 2. 启动之后发生什么

```
python3 main.py
    │
    ├─ 读 config/default.yaml
    ├─ 创建 AppContext（机器人、夹爪、压机、相机、VisionService、gvl…）
    ├─ 创建 Coordinator（主循环线程，约 50ms 一拍）
    └─ 打开 MainWindow（HMI）+ 可选弹出「相机监控」
```

入口文件：`main.py`。

每一拍主循环（`core/coordinator.py`）大致做：

1. 把 HMI 按钮状态同步到内部运行标志（Running / Paused / Stop / 急停等）  
2. 若在初始化：跑 `stations/init_sequence.py`  
3. **并行**调用 Station1～6 的 `cycle(ctx)`（各站自己判断能不能进、当前哪一步）  
4. 刷新三色灯、处理通信掉线等  

HMI 另有 **快/慢定时器**刷显示（`hmi/main_window.py`），与 OB1 **同进程共享 ctx**，详见 §3.3。

### 3.1 Mem 和全局变量写在哪个文件

Mem **不走网口**。它是本机 BOOL，对照 Codesys `GVL_Memory`。工位之间靠 Mem 握手；对真机的读写见 §3.2。

| 对象 | 定义文件 | 运行时挂在 | 谁写 | 谁读 |
|------|----------|------------|------|------|
| `Memory_BOOL[1..10]` | `core/gvl.py`（`GVL.__init__`） | `ctx.gvl.Memory_BOOL` | 工位 `sync_mem`；HMI 勾选先写 `ctx.memory`，周期开头灌进 GVL | 各 `stations/station*.py` 进入条件 / 分支 |
| Mem 中文名 | `core/memory.py` 的 `MEMORY_LABELS` | — | 改源码 | 总览勾选文字、i18n 可另有一套显示 |
| HMI 勾选副本 | `core/memory.py` 的 `MemoryBank` | `ctx.memory` | `sync_mem`；总览勾选 `monitor_page.py` | 总览刷新 |
| 写记忆入口 | `core/plc_util.py` 的 `sync_mem` | — | 工位必须走这里（同时写 GVL + HMI） | — |
| 两边对齐 | `core/coordinator.py` `_sync_main_flags` / `cycle` 末尾 | — | 周期开头：界面→GVL；周期末：GVL→界面（若不一致） | — |
| `Main`（Running/Paused/InitDone…） | `core/gvl.py` 的 `MainFB` | `ctx.gvl.Main` | Coordinator、初始化、HMI 命令 | 各 Station |
| `Station[n].Auto_A` / `Busy` | `core/gvl.py` 的 `StationFB` | `ctx.gvl.Station[1..6]` | 该站 `cycle` 改步号 | 工位调试页、监控 |
| `PickPose` / `BeltPickSnapshot` | `core/gvl.py` | `ctx.gvl` | Station1 拍照成功 | Station2 取料、Mem8/9 回退 |
| `BeltDiRaw` / `BeltPresent` | `core/gvl.py` | `ctx.gvl` | OB1 `update_belt_present` 滤波原始光电 | Station1 进入条件；HMI 显示中转 |
| 发令锁存 `_cmd_latch`、延时 `_delay_until` | `core/gvl.py`（内部） | `ctx.gvl` | `pulse_cmd` / `delay_*` | 各站防重复发 Move |
| 机台状态 IDLE/READY/RUNNING… | `core/machine_state.py` | `ctx.machine` | Coordinator 命令 | 灯语、HMI 按钮使能 |
| 报警队列 | `core/alarm.py` | `ctx.alarms` | `ctx.raise_alarm` | 弹窗、报警页 |
| IP / 点位 / Mock / 步速 | `config/default.yaml` | `ctx.cfg` | HMI 保存写回 yaml | 启动时 `load_config` |
| 中科院点表（Excel Dec） | `devices/plc_cas_points.py` | `PressMachine.cas_point_list()` | yaml `press.cas_points` 可覆盖地址 | 压机读写、HMI 点表页 |
| 压机缓存线圈/保持寄存器 | `devices/press_modbus.py` 的 `_cas_coils` / `_cas_holdings` | `ctx.press` | `cas_write`、IO 线程真读回填 | `cas_read`（工位/HMI **只读缓存**） |

**Mem 含义（`MEMORY_LABELS`）：**

| Mem | 含义 | 主要写入站 | 主要读取站 |
|-----|------|------------|------------|
| 1 | 皮带上料拍照完成 | S1=1；S2 取完清 0 | S1 进入要=0；S2 取料要=1 |
| 2 | 机器人1手爪有料 | S2 取完=1、放完=0 | S2 放料、S3 进入 |
| 3 | 放料鞋槽有料 | S2 放完=1；S3 按判定改；S6 转完清 | S2 放料要=0；S6 进入要=1 |
| 4 | 放料鞋槽拍照完成 | S3=1；S6 转完清 | S2 放料要=1；S3 进入要=0 |
| 5 | 机器人2手爪有料 | S5 取完=1、放完=0 | S5 取/放分支 |
| 6 | 取料鞋槽有料 | S4=槽内有料；S5 取完清 0 | S5 取槽要=1；S6 进入要=0 |
| 7 | 取料鞋槽拍照完成 | S4=1；S6 转完清 | S4 进入要=0；S6 进入要=1 |
| 8 / 9 | 上料爪左鞋 / 右鞋 | S2 取完写、放完清 | S2 对位/压跟侧；S3 左右匹配 |
| 10 | 放料鞋槽不匹配（只转不压） | S3 判定；S6 转完清 | S2 禁放；S6 启动字 1=空转 / 2=启动 |

工位程序里：`M = gvl.Memory_BOOL`，写位只用 `sync_mem(ctx, 序号, True/False)`。

### 3.2 整机通讯方式（含读写）

原则：

1. **Mem / GVL / 步号** = 进程内变量，**不是** Modbus。  
2. **主循环（OB1，约 50ms）不直接堵在 TCP 上**：压机真读写在独立线程 `press-modbus`；工位调 `cas_read` 只看缓存，`cas_write` 先改缓存再排队下发。  
3. 各设备 `use_mock=true` 时不建真连接，读写打在本机模拟状态上。  
4. 地址改 `config/default.yaml` 或 HMI「设置 → 通信与设备」「压机信号」，不要改驱动源码。

#### 通道总表

| 设备 | 物理通道 | 协议 / SDK | 驱动文件 | 读 | 写 |
|------|----------|------------|----------|----|----|
| 上料/下料臂 | 以太网 TCP | 法奥 Fairino **XML-RPC**（约 **20003 / 20005**） | `devices/robot_fr5.py` | 关节/TCP 位姿、故障、`GetDI`（皮带光电）、运动是否到位 `poll_move_done` | `MoveJ`/`MoveL`、`SetSpeed`、负载/工具号、JOG |
| 压鞋机 PLC | 以太网 TCP **502** | **Modbus TCP**（pymodbus，站号 `press.unit_id`） | `devices/press_modbus.py` | 见下表功能码 | 见下表功能码 |
| 夹爪电机 | SocketCAN `can0` 或达妙 USB2CAN **`/dev/ttyACM0`** | CAN **1 Mbps**，位置速度模式 | `devices/gripper_can.py` | 反馈帧：到位、故障 | 使能、目标开合位置+速度 |
| 相机 cam1～4 | USB（Orbbec serial） | pyorbbecsdk；失败再试 OpenCV | `vision/camera_orbbec.py` | 彩色/深度帧 | 无工艺写（仅开流参数） |
| 工控机急停/灯 | yaml `io.*` | 当前实现多为内存位 | `devices/io_manager.py` | `read_estop` | `write_lights`；急停另经压机 `host_estop` 线圈下发 |

掉线：Coordinator 每拍 `probe_all_device_links`，真机断则 **LINK** 报警；压机 IO 线程约 3s 重连一次。

#### 压机 Modbus：功能码与点

Excel Dec → PDU 在 `devices/plc_cas_points.py`（`pdu_addr` / `hmi_modbus_dec`）。  
HMI「压机信号」页可改 Dec 覆盖到 `press.cas_points`。

| PLC 区 | 点表示例 | 读（IO 线程） | 写（IO 线程） | 程序封装 |
|--------|----------|---------------|---------------|----------|
| **D 保持寄存器** | 空闲、启动、放鞋完成、当前工位显示 | **FC03** `read_holding_registers` | 先 **FC16** `write_registers`（单字列表），失败再 **FC06** `write_register`（台达奇数地址常拒 FC06） | `cas_read` / `cas_write` |
| **M 线圈** | 联机模式、急停 host_estop、1～4 槽工作完成 | **FC01** `read_coils` | **FC05** `write_coil` | 同上 |
| **X 离散输入** | 点表里若有 | **FC02** `read_discrete_inputs`，失败再试线圈 | 不可写 | `cas_read` |

调用约定：

- 工位/HMI **读**：`press.cas_read(point)` 或 `cas_word("idle")` → **只读缓存**，不占用 OB1。  
- 工位/HMI **写**：`cas_write` / `set_shoe_placed` / `set_press_run_mode` / `set_host_estop` → 先改缓存，再 `_enqueue` 给 IO 线程 `_cas_write_io`。  
- IO 线程空闲时 `_poll_runtime` 把监视点刷回缓存。HMI 可用 `request_cas_poll` 指定要刷的 id。

**联机字（自动流程真正用到的）：**

| 点 id | 方向 | 含义 | 谁写 | 谁读 |
|-------|------|------|------|------|
| `online` | 工控机→PLC（M） | 联机模式 | 写放鞋完成/启动时顺带置 1 | PLC |
| `idle` | PLC→工控机（D） | 1=空闲=转盘到位 | PLC（Mock 由本机模拟忙闲） | S3/S4/S5/S6 进入；`press.rotate_done` |
| `shoe_done` | 工控机→PLC（D） | 放鞋完成 1/0 | S2 放完置 1；S6 步10 保证为 1；停止/初始化 **清一次 0** | PLC；S6 保持计时 |
| `start` | 工控机→PLC（D） | 0 关 / **1 空转** / **2 启动** | S6 步20（须 `shoe_done=1` 且满 `press.shoe_done_hold_s`，默认 500ms）；停止/初始化清 0 | PLC |
| `station_no` | PLC→工控机（D） | 当前工位显示（放料工位） | PLC（Mock 跟放料槽号） | 推算取料槽号 |
| `s1..s4_slot_done` | PLC→工控机（M，只读） | 该槽取料工作完成 | PLC | `is_pick_work_done()`：先用 `station_no` 按槽顺序推出取料槽，再读该槽线圈 |
| `host_estop` | 工控机→PLC（M） | 开=本机急停，关=急停复位 | Coordinator `_sync_press_host_estop` | PLC |

槽号顺序、点进点退等手动点在点表其它行，同样走 `cas_read`/`cas_write`，不经过 Mem。

#### 各 Station 实际碰哪条通讯

| Station | 读（真机） | 写（真机） | 只碰 Mem（本机） |
|---------|------------|------------|------------------|
| **S1** | 上料臂 **GetDI** 光电（滤波进 `gvl.BeltPresent`）；**cam1** 一帧 | 无运动 | 拍完 `Mem1=1` |
| **S2** | 臂到位/故障；夹爪到位；**cam2** 对位图 | MoveJ/L；夹爪开合；**放鞋完成=1**（Modbus） | 取/放后改 Mem1/2/3/8/9 |
| **S3** | 压机 **空闲**（缓存）；**cam3** | 无 | 按判定写 Mem3/4/10 |
| **S4** | 空闲；**取料槽工作完成**（线圈缓存）；**cam4** | 无 | 写 Mem6/7 |
| **S5** | 空闲；取料槽工作完成；下料臂/夹爪 | MoveJ/L；夹爪 | 写 Mem5/6 |
| **S6** | 空闲 | 放鞋完成、启动 1/2、结束清 0 | 进入看 Mem3/7/6/10；结束清 Mem10/3/7/4 |
| **Init** | 臂连接；压机 connected / power_ok | 双臂回 home；夹爪闭合；清放鞋完成与启动各一次 | 不改工艺 Mem |

皮带光电：`robots.robot1.di_belt_sensor` 读原始 DI，OB1 滤波后写入 `gvl.BeltPresent`（中转）。Station1 只看中转，再等 `belt_photo_delay_ms`（默认 500）才拍。滤波时间 `belt_filter_ms`（默认 50）。无真光电可 `di_belt_use_mock`。HMI：**总览 → 手动 IO**、**视觉 → cam1**、**通信配置**。

#### 视觉读写

工位调用 `ctx.vision.photo_*` / `guide_*`（`vision/vision_service.py`）：

- **读**：向对应 `OrbbecCamera` 取图。默认 `vision.orbbec_backend=rsdt` 走 `RSDT_Simple_Automation` 的奥比驱动（`connect_camera` / `get_one_frame`，含热插拔与对齐）；失败再本仓 pyorbbecsdk / OpenCV。Mock 仍用测试图。  
- **算**：`algorithm_module`（纯 CPU，无设备 IO）。  
- **写盘**：生产拍照可写 `logs/vision_snaps/`（开关 `vision.save_runtime_snaps`）；**不写**机器人、不写 Mem（Mem 由 Station 在判定成功后再 `sync_mem`）。

#### HMI 与主循环（摘要）

详见 **§3.3**。界面不另开一套协议：和主循环同进程，共享 `ctx`。按钮调 `coord.cmd_*`；显示靠定时器读内存。

### 3.3 前端（HMI）和后端怎么通讯

这里的「前端」是工控机上的 **PySide6 窗口**（`hmi/`），「后端」是 **Coordinator 主循环 + 设备线程**（`core/`、`stations/`、`devices/`）。  
**不是**浏览器 ↔ 独立 HTTP API（那是可选的手机页，见本节末）。主界面和扫描循环在 **同一个 `python3 main.py` 进程**里。

#### 启动时谁先谁后

```
main.py
  AppContext          建 gvl / 机器人 / 压机 / 相机
  ctx.connect_all()   连设备
  Coordinator.start_thread()   后台线程名 OB1，约 50ms cycle()
  MainWindow(coord)   Qt 界面；页里拿 coord 和 coord.ctx
  （可选）手机 Web 线程  8765
  app.exec()          Qt 事件循环占主线程
```

退出：先停手机 Web → `coord.stop_thread()` → 关灯。

#### 线程分工（同进程，不是网络）

| 线程 | 做什么 | 和界面怎么见面 |
|------|--------|----------------|
| **Qt 主线程** | 画按钮、收点击、弹窗 | 只在这里改控件 |
| **OB1** `coordinator._run` | 扫 Station、初始化、掉线、灯 | 写 `ctx.gvl` / `machine` / 报警队列 |
| **press-modbus** | 压机 Modbus 真读写 | 界面/工位只碰缓存 `cas_read`/`cas_write` |
| **cam-stream-*** | 各路相机取流 | 写入 `OrbbecCamera.last_color` |
| **LiveGrabber** | 监控窗把 last_color 拷到 vision | 监控页读缓存，不经 Coordinator |
| **MobileWeb** | HTTP 8765 | 浏览器轮询；命令仍调 `coord.cmd_*` |

没有「前端发 JSON 给后端再回」这一层。共享对象就是总线。

#### 界面 → 后端（写：命令）

按钮 **直接调用** `Coordinator` 方法（在 Qt 线程里进函数，改状态；真正运动在下一拍 OB1）：

| 操作 | 调用 | 文件 |
|------|------|------|
| 初始化 / 启动 / 暂停 / 停止 / 急停 / 急停复位 / 报警复位 | `coord.cmd_init` 等 | `hmi/pages/monitor_page.py` 绑定 |
| 单步武装、执行步 | 改 `gvl.Station` + 模式 | `hmi/pages/step_debug_page.py` |
| 改 Mem 勾选 | `ctx.memory[i]=` | 总览；OB1 开头灌进 `gvl.Memory_BOOL` |
| 保存 IP/点位 | `save_config` 写 `config/default.yaml`，并改 `ctx` 上的对象 | 各设置页 |
| 点表写线圈 | `press.cas_write`（进压机 IO 队列） | 压机信号页 |
| 手动 Move / 夹爪 | `ctx.robot1.move_*`、`gripper.open` | 示教 / 夹爪调试（尽量避开自动运行） |

`cmd_*` 会改 `ctx.machine` 状态（IDLE / READY / RUNNING / PAUSED / STOPPED / ALARM / ESTOP）。OB1 每拍 `_sync_main_flags` 把这些抄到 `gvl.Main.Running/Paused/Stop/...`，各 Station 只看 GVL。

**不要**在界面线程里长时间 `wait` 真机到位；工位用 `pulse_cmd` + `poll_move_done` 在 OB1 里等。

#### 后端 → 界面（读：显示）

Qt **定时器**拉状态，不订阅 Socket：

| 定时器 | 周期（yaml `system.hmi`） | 做什么 |
|--------|---------------------------|--------|
| `_fast_timer` | `refresh_fast_ms` 默认 33ms | 顶栏三色灯；总览/工位调试/点位等 `refresh_fast` |
| `_slow_timer` | `refresh_slow_ms` 默认 200ms | 当前页 `refresh`；`alarms.pop_popup()` 弹可复制报警窗 |

页面读：`ctx.gvl` 步号、`ctx.memory`、`ctx.machine`、`press.cas_read` 缓存、`robot.get_actual_tcp_pose`（示教页）、相机 `last_color`。  
报警：Station/`raise_alarm` 入队 → GUI 慢刷弹出，避免在 OB1 里弹 Qt 窗。

#### 图像怎么到画面

生产拍照：Station → `VisionService.photo_*` → `cam.grab()`（RSDT/本仓驱动）→ `algo` → 可写 `logs/vision_snaps/`。  
相机监控：流线程填 `last_color`，LiveGrabber 拷到 `vision.last_raw`，监控页刷新显示。**不经过 Coordinator，也不走 HTTP。**

#### 手机页（唯一真正的 HTTP）

`mobile/web_server.py`，`system.mobile_web.enabled` 打开后：

| 方向 | 接口 | 作用 |
|------|------|------|
| 读 | `GET /api/status` | JSON 快照：状态、Mem、工位忙闲、压机、报警 |
| 读 | `GET /api/ping` | 探活；可带 token |
| 写 | `POST /api/cmd/init` 等 | 内部还是 `coord.cmd_init()`，与桌面按钮同一套 |

这不是给主 HMI 用的。RSDT 仓库里的 FastAPI/WebRTC **本程序主界面不用**。

#### 和设备通讯的关系

HMI↔后端 = 进程内共享 `ctx`。  
后端↔设备 = §3.2（法奥 XML-RPC、压机 Modbus、夹爪 CAN、奥比驱动）。  
两层不要混：界面永远不要自己去 `Robot.RPC()` 或 pymodbus。

## 4. 一条鞋的主流程（自动模式）

互锁靠记忆位 `Mem1～10`（界面「运行监控」可勾选查看）。概念顺序如下：

```
① Station1  皮带 cam1 拍照
            → 得到 PickPose（基座坐标 + 左右脚）
            → 置相关记忆（如拍照完成）

② Station2  上料臂 Auto 取料段
            → 到取料进入点 / 上方 / 下降取料 / 夹紧 / 抬起 / 退出
            → 手爪有料

③ （需要时）Station3  放料槽 cam3 拍照：槽是否空、方向是否匹配

④ Station2  上料臂 Auto 放料段
            → 进入点 → 上方 → 接近放料点 →（鞋头 TCP）对位 → 压跟
            → 张爪 → 上方 → 退出
            → 槽侧待压合/转台相关记忆

⑤ Station6  先发放鞋完成=1，保持约 500ms 后再写启动（2）或空转（1）
            → 空闲变 0 → 再等空闲=1（转盘到位）→ 清令、推进槽号

⑥ Station4  取料槽 cam4：有无鞋；有则测压杆 XY 偏移

⑦ Station5  下料臂：取槽 → 皮带放料 → 记一件产量

然后下一只鞋继续 ①…
```

### 4.1 Station 一览

| Station | 文件 | 职责 |
|---------|------|------|
| 1 | `stations/station1_belt_photo.py` | 皮带拍照 → PickPose |
| 2 | `stations/station2_robot1.py` | 上料取料 + 放料（含鞋头对位） |
| 3 | `stations/station3_place_slot_photo.py` | 放料槽视觉 |
| 4 | `stations/station4_pick_slot_photo.py` | 取料槽视觉 + 压杆 |
| 5 | `stations/station5_robot2.py` | 下料取放 |
| 6 | `stations/station6_press_rotate.py` | 放鞋完成→启动/空转→等压机忙闲→推进槽号 |
| Init | `stations/init_sequence.py` | 上电初始化 |

每个 `cycle(ctx)` 典型结构：

1. 更新本站是否 Busy（有步号在跑则为忙）  
2. 停机/急停/报警 → 步号清零  
3. **进入条件**满足 → 把某条 Auto 的步号设为 10  
4. 未暂停时按当前步号 `match/case` 执行：发一次运动或等待完成，再跳下一步  

**为什么运动要「发一次」？**  
主循环每 50ms 扫一次。若每拍都发 Move，会重复下发。工程里用 `pulse_cmd`：某一步里第一次返回允许发令，之后只轮询到位。

### 4.2 Station2 放料路径（便于对照代码）

```
进入点 → 上方 → 接近放料点(工具1) → 切鞋头TCP → 对位 → 压跟 → 张爪 → 上方 → 退出
```

对位逻辑在 `stations/toe_place_assist.py`，调用 `algo.classify_toe_align`。

### 4.3 Station6 与压机联机字

进入（并行，其它站不因此停）：Mem3=1、Mem7=1、Mem6=0、压机空闲=1、本站不忙、自动运行未暂停。

```
步10  写放鞋完成=1（若上料已提前写过且已满保持时间，不再额外等一轮）
步20  保持时间到（默认 500ms，yaml press.shoe_done_hold_s）才写启动=2 或空转=1
步30  等空闲变 0；press.idle_go_busy_timeout_s=0 则一直等
步40  等空闲=1（转盘到位）
步50  启动=0、放鞋完成=0，推进槽号，清 Mem10/3/7/4
```

**停止：** 双臂停；放鞋完成/启动各写 0 **一次**；清 InitDone，下次必须再初始化。暂停不清联机字、可直接继续。初始化开始时同样清一次放鞋完成和启动。

取料槽工作完成由压机 PLC 给出（只读），跟「当前工位显示」推取料槽。S4/S5 等该位=1。

## 5. 视觉怎么接到流程上

```
工位 stations/*
    → ctx.vision.photo_* / guide_*     （VisionService：取图、Mock、监控图）
        → algo.*                         （algorithm_module：检测/分类）
            → vision/legacy_pipeline 等   （YOLO / 手眼实现）
```

| 相机 | 作用 | 主要入口 |
|------|------|----------|
| cam1 | 皮带找鞋 → 取料坐标 | `photo_belt_pick` → `algo.detect_belt_pick` |
| cam2 | 鞋头是否到位 | `guide_place_edge` / toe_place_assist → `algo.classify_toe_align` |
| cam3 | 放料槽有无鞋 | `photo_place_slot` → `algo.classify_slot_occupied` |
| cam4 | 取料槽 + 压杆偏移 | `photo_pick_slot` → classify + `measure_rod_offset_mm` |

相机 Mock 时：皮带可用 HMI「屏蔽取料」示教点；详见算法 readme。

监控窗：`visualize_module` 取流 + 可选实时推演（缓存帧调 `compute_monitor`）。**推演不落盘。**

生产拍照（Station1/3/4 与视觉「检测测试」）会把原图/叠图/检测结果写入 `logs/vision_snaps/`（jpg 文件名含相机与时间）；放入鞋槽、槽判定、下料放皮带后再写回同一条 `transport`。HMI **报警记录 → 运行快照** 可翻历史并打开该文件夹。监视刷新不存。详见 [界面操作手册.md](界面操作手册.md) §14.4 与软件内「使用说明」同名章节。

## 6. 运动指令

工位 / 点位页最终调用：

| 封装 | 法奥 SDK | 用途 |
|------|----------|------|
| `robot.move_j(...)` | **MoveJ** | 关节空间（建议示教时存 j1..j6） |
| `robot.move_l(...)` | **MoveL** | 直线笛卡尔 |
| `robot.follow_quintic_spline(points)` | RSDT `RobotServoSpline` | 多点五次样条 + ServoCart |
| 全局速度 | SetSpeed | 运行监控百分比 |

底层 RPC 可换：`robots.rpc_backend`（HMI 设置→通信与设备）。**rsdt** 用 `RSDT_Simple_Automation` 的 `FairinoRobotArm`（导入失败自动退回本仓 SDK）；**fr5** 直接 `Robot.RPC`。工位仍只调 `RobotFR5`，不要直接调 RSDT。

按**程序步**调速：HMI「运动参数」→ yaml `motion_steps` → `ctx.step_motion_kwargs("s2a10_30")`。
